# knowledge-graph

A repeatable pipeline for a repository's two knowledge graphs:

- the **docs graph**: [docs-curator](../docs-curator/README.md) curates the documents, then Graphify builds the graph from them;
- the **code graph**: [codegraph](https://github.com/colbymchenry/codegraph), used through [code-graph](../code-graph/README.md).

The `kg` script handles every mechanical step, including the workarounds that used to be done by hand. The skill handles the steps that need judgment and always asks you before spending tokens.

## What kg does for you

kg turns a repository's documents and code into two searchable knowledge graphs, and keeps them current as the repo changes. Each point below says what you get, then how kg delivers it.

### For everyone: why you can trust the graph

- **Only reviewed content goes in.** The docs steps run only on `main`, `develop` or `develop-*` with a clean working tree, so the graph never reflects half-finished or unmerged work. `--allow-any-branch` overrides this, and every override is logged.
- **Sensitive data stays out.** Paths listed in `phi_globs` are always excluded, and their extracted text is purged after every analyze. If any trace of them appears in the text cache, staging or the graph, the run stops with exit code 4. It is a hard stop, not a warning.
- **A bad run can be undone.** The graph, graphify's semantic cache, the docs-curator state, per-file decisions and verdicts are saved before each curate and each graph run. The last 3 snapshots are kept, and `kg restore` puts one back. Retries can never push out the last good graph.
- **Spend is visible before it happens.** Each graph run shows a token-cost estimate (from `cost.json`) and stops for a separate, explicit yes if it passes the cap. Lost nodes are sorted into "from changed files" and "unexplained" before anything is forced through.

### For managers: less rework, predictable cost

- **Review effort is spent once.** When a document cluster is renumbered because a member changed, its earlier verdict carries over if the old and new member sets overlap by at least 80%, and moved files are followed. Reviewers see only the new members, not the whole cluster again. Clusters where fewer than two members can reach staging are closed automatically (`kg_auto`) and reopened if an override gives them a second.
- **Incremental runs cost less.** Manifests written by older versions are re-keyed, so `--update` re-extracts only the files that changed.
- **Naming stays stable.** Community labels carry forward wherever at least 50% of a community's labelled members agree, so the graph's vocabulary doesn't churn between runs.
- **Nothing is lost silently.** The keeper check catches documents that dropped out of staging because their duplicate's keeper was also excluded.

### For developers: control and repeatability

- **Overrides are generated, not hand-maintained.** `overrides.yaml` is built from git (only tracked documents are staged), the exclude groups in `kg.yaml`, and your hand decisions in `overrides.manual.yaml`. The file rules are imported from docs-curator's `curate.py`, so they can't drift from it.
- **Graph excludes are declarative.** `graph.excludes` in `kg.yaml` holds gitignore-style patterns such as `*.xlsx.md` or `!/specs/api/decp.openapi.yaml.md`. kg writes them into graphify's exclude file before each run, so new files follow the rules too, and it prunes the nodes of files the rules newly exclude.
- **Hand corrections survive re-extraction.** `graph-fixups.yaml` next to `kg.yaml` lists reviewed fixes (links to add, duplicate nodes to merge) that kg applies after every run. Self-loop edges are always dropped.
- **Oversized files are planned for.** A graph run lists files that need their own extraction chunk instead of failing midway.
- **Code graph in one command.** `kg code` runs `codegraph sync` on any branch and keeps codegraph's telemetry off.
- **Portable setup.** The repo's `graphify-out` and `.docs-curator` symlinks are written as `$HOME` paths, so they work on other machines.

## Layout

```text
~/curated/<repo>/             # its own git repo; only the hand-made files are tracked
├── kg.yaml                   # pipeline settings (source, gate, phi_globs, exclude groups, thresholds, related repos)
├── config.yaml               # docs-curator settings
├── overrides.manual.yaml     # hand decisions, take precedence over generated rules
├── overrides.yaml            # generated by kg
├── staging/  .docs-curator/  graphify-out/
├── backups/<timestamp>/      # snapshots
└── .kg/                      # run log, cluster registry, review list, graph plan, label proposals
```

## Example kg.yaml

`kg init` writes a starting `kg.yaml` like the one below. Every key except `source` is optional; leaving one out uses the default shown. Globs follow `fnmatch` rules, where `*` also matches `/`, and are relative to the repo root. The one exception is `graph.excludes`, which uses gitignore-style patterns relative to `staging/`. Unknown keys are rejected.

```yaml
source: ~/Projects/my-repo           # the repo this folder curates; must match where kg runs

gating:                              # docs steps only (curate, apply, graph); codegraph sync runs anywhere
  branches: [main, develop, "develop-*"]
  require_clean: true

phi_globs:                           # never extracted or staged; any trace stops the run (exit 4)
  - "data/customer-exports/*"
  - "build/uploads/*/applications/*"

overrides:
  tracked_only: true                 # stage only git-tracked documents
  exclude_groups:                    # tracked, but not documentation
    - note: "test fixture"
      globs: ["*/src/test/*", "tests/*"]
    - note: "build/tool config"
      globs: ["pom.xml", "*/pom.xml", "package.json", "*/package.json"]
    - note: "agent tooling (not product docs)"
      enabled: false                 # listed but off; `kg overrides --dry-run` shows what it would drop
      globs: [".claude/*", ".github/prompts/*"]

known_excluded_keepers: []           # excluded files whose keeper is also excluded, already checked

carry_forward:
  verdict_overlap: 0.8               # copy a verdict to a re-numbered cluster at this member overlap
  label_agreement: 0.5               # reuse a community label when this share of members agrees
  label_min_known: 0.5               # ...and at least this share of all members had a label before
  subset_max_members: 25             # a cluster that only lost members keeps the verdict of an old one this small

graph:
  cost_cap_tokens: 1500000           # an estimate above this needs a separate, explicit yes
  agent_overhead_tokens: 60000       # fixed cost per extraction agent, added to the estimate
  big_file_bytes: 400000             # changed files over either limit get their own chunk
  big_file_line_chars: 20000
  excludes:                          # which staged files reach the graph; last match wins
    - "*.xlsx.md"                    # spreadsheets: mostly rows, costly
    - "*.json.md"
    - "*.pptx.pdf"                   # decks; their .pptx.notes.md speaker notes stay in
    - "/docs/form-library/**/*.pdf.md"
    - "!/specs/api/openapi.yaml.md"  # but the API contract does go in

backups:
  keep: 3                            # newest snapshots kept, plus the pre-run one of an unfinished graph run

related_repos:                       # other repos whose graphs are read-only from here
  - name: config-repo
    path: ~/Projects/config-repo
    graph: ~/Projects/config-repo/graphify-out/graph.json
    mapper: map_config_refs.py       # optional script in this folder; run by `kg apply`
```

## Usage

```bash
kg init ~/Projects/my-repo        # once; then fill in phi_globs in kg.yaml
kg preflight --fix
kg status                         # where things stand and the next step
kg all                            # scripted steps up to the next one that needs a person
kg review                         # clusters waiting for a verdict or a re-check
kg graph prepare                  # before the graphify run: cost estimate, plan
kg graph check | labels | finish  # around graphify's merge and labelling steps
kg code                           # codegraph sync
kg restore [<timestamp>] --yes
```

Ask Claude to "refresh the knowledge graphs" and the skill runs these commands, stopping for your input where needed.

## Files

- `SKILL.md`: the workflow Claude follows, gates, exit codes and hard rules
- `scripts/kg.py`: the pipeline script (a single PEP 723 file run with `uv run --python 3.12 --script`)
- `tests/test_kg.py`: pytest suite covering gating, overrides, PHI, carry-forward, node-loss check, labels, snapshots, links and manifest re-keying

## Requirements

`uv`, Python 3.12 (uv fetches it), the docs-curator, heavy-file-ingestion, code-graph and graphify skills, the `graphify` CLI 0.9.103 or later, and `codegraph`. kg never installs any of them.
