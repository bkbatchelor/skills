# knowledge-graph

A repeatable pipeline for a repository's two knowledge graphs:

- the **docs graph**: [docs-curator](../docs-curator/README.md) curates the documents, then Graphify builds the graph from them;
- the **code graph**: [codegraph](https://github.com/colbymchenry/codegraph), used through [code-graph](../code-graph/README.md).

The `kg` script handles every mechanical step, including the workarounds that used to be done by hand. The skill handles the steps that need judgment and always asks you before spending tokens.

## What kg does for you

- **Gate**: the docs steps only run on `main`, `develop` or `develop-*` with a clean working tree, so the graph reflects only reviewed, merged content. `--allow-any-branch` overrides this, and every override is logged.
- **PHI**: paths listed in `phi_globs` are always excluded. Their extracted text is purged after every analyze. Any trace of them in the text cache, staging or the graph stops the run with exit code 4.
- **Overrides**: `overrides.yaml` is generated from git (only tracked documents are staged) plus the exclude groups in `kg.yaml` and your hand decisions in `overrides.manual.yaml`. The file rules are imported from docs-curator's `curate.py`, so they can't drift from it.
- **Verdict carry-forward**: when a cluster gets a new ID because a member changed, its verdict is copied across if the old and new member sets overlap by at least 80%. Moved files are followed. Only the new members are listed for review.
- **Auto-close**: a cluster where fewer than two members can reach staging gets a verdict marked `kg_auto`, because there is nothing to judge. The verdict is reopened automatically if an override change gives it a second member that can reach staging.
- **Keeper check**: catches documents that silently left staging because their duplicate's keeper is also excluded.
- **Snapshots**: the graph, graphify's semantic cache, the docs-curator state, per-file decisions and the verdicts are saved before each curate and each graph run. The last 3 are kept, and `kg restore` puts one back. Unchanged state is not snapshotted twice, and the snapshot an unfinished graph run started from is never pruned, so retries can't push out the last good graph.
- **Graph runs**:
  - A token-cost estimate from `cost.json`, with a cap.
  - A list of oversized files that need their own extraction chunk.
  - Lost nodes sorted into "from changed files" and "unexplained" before `force=True`.
  - Community labels carried forward wherever at least 50% of a community's labelled members agree.
- **Manifest re-keying**: rewrites graphify manifests written by older versions so that `--update` only re-extracts the files that changed.
- **Links**: the repo's `graphify-out` and `.docs-curator` symlinks are written as `$HOME` paths, so they work on other machines.
- **Code**: `kg code` runs `codegraph sync` on any branch and keeps codegraph's telemetry off.

## Layout

```text
~/curated/<repo>/             # its own git repo; only the hand-made files are tracked
├── kg.yaml                   # pipeline settings (source, gate, phi_globs, exclude groups, thresholds, related repos)
├── config.yaml               # docs-curator settings
├── overrides.manual.yaml     # hand decisions, take precedence over generated rules
├── overrides.yaml            # generated by kg
├── staging/  .docs-curator/  graphify-out/
├── backups/<timestamp>/      # snapshots
└── .kg/                      # run log, cluster registry, review list, graph plan, label proposals
```

## Usage

```bash
kg init ~/Projects/my-repo        # once; then fill in phi_globs in kg.yaml
kg preflight --fix
kg status                         # where things stand and the next step
kg all                            # scripted steps up to the next one that needs a person
kg review                         # clusters waiting for a verdict or a re-check
kg graph prepare                  # before the graphify run: cost estimate, plan
kg graph check | labels | finish  # around graphify's merge and labelling steps
kg code                           # codegraph sync
kg restore [<timestamp>] --yes
```

Ask Claude to "refresh the knowledge graphs" and the skill runs these commands, stopping for your input where needed.

## Files

- `SKILL.md`: the workflow Claude follows, gates, exit codes and hard rules
- `scripts/kg.py`: the pipeline script (a single PEP 723 file run with `uv run --python 3.12 --script`)
- `tests/test_kg.py`: pytest suite covering gating, overrides, PHI, carry-forward, node-loss check, labels, snapshots, links and manifest re-keying

## Requirements

`uv`, Python 3.12 (uv fetches it), the docs-curator, heavy-file-ingestion, code-graph and graphify skills, the `graphify` CLI 0.9.103 or later, and `codegraph`. kg never installs any of them.

## Tests

```bash
uv run --no-project --python 3.12 --with pytest --with pyyaml pytest docs/knowledge-graph/tests
```
